# Draw It or Lose It - Software Design Project
# Project Summary
The Gaming Room is a client that wanted to expand its existing Android game, Draw It or Lose it, into a web-based application that could be accessed from different operating systems and devices. The game allows multiple teams and players to participate and the application needs to manage unique game and team names while keeping game information consistent for everyone. The goal of the project was to develop a software design that would support these requirements while allowing the application to grow and support more users.  
# What I Did Well
I think one of the things I did particularly well was keeping the software design document straightforward and easy to understand. I appreciate documentation that gets to the point and presents information clearly without unnecessary complexity. While detailed technical explanations have their place, I think it's important to communicate the most relevant information when helping a client make a decision. I tried to explain my recommendations in a way that was informative without being overly complicated. 
# How the Design Document Helped
The UML diagram was the most helpful part of the design process for me. I am a visual learner, and I sometimes struggle to understand how everything works together when reading code. Seeing the classes, attributes, methods, and relationships laid out in a diagram made it easier to understand how the application was organized. It also helped me see how the different classes connect and how the code should be structured before beginning development.
# What I Could Improve
If I could improve one part of this project, I would like to create my own UML diagram rather than using the one provided in the template. The diagram was helpful in understanding how the classes relate to each other, but I think building it myself would have given me a better understanding of how the code fits together. I also learned the importance of verifying that technical information is current. During my research, I discovered that some of the information about macOS Server was outdated and needed to be revised. Technology changes constantly, and I think keeping up with those changes is an important part of software development.
# Understanding the Client's Needs
When developing my software design, I focused primarily on what would be practical and affordable for The Gaming Room. I wanted to recommend technologies that would meet the company's current needs while allowing room for future growth. This influenced my recommendation of Linux as the server operating system and AWS cloud services for storage. I believe that having a reliable and well-organized system provides a strong foundation for a quality product. While I focused more on the company's technical needs than the individual player experience, I recognize that both are important. Understanding the client's needs helps developers make decisions that support the goals of the project without adding unnecessary costs or complexity.
# My approach to Software Design
My main approach to designing the software was research. Since many of the operating systems and technologies were new to me, I spent time learning about the different options and comparing their advantages and disadvantages. I wanted to understand how each technology worked and how the different components could work together before making recommendations. In future projects, I would continue using research as my starting point, along with UML diagrams to help me visualize how the software is organized. I also learned that it is important to verify information because technology is constantly changing.
